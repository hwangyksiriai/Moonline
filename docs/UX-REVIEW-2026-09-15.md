# Moonline 사용자 관점 UX 리뷰

검토일: 2026-09-15 / 대상: 글라스모피즘과 산세리프 적용 후 Expo MVP 0.2

## 결론

현재 앱은 따뜻한 시각적 분위기와 예약→수신→기록의 연결은 갖췄다. 하지만 첫 통화까지의 입력 부담, 목소리 선택의 확신, 대기 중 준비 상태, 통화의 실재감, 같은 사람과 다시 만나는 편의가 부족하다. 화면 장식을 더하는 것보다 “내가 고른 사람에게 쉽게 전화받고, 내 말을 존중받고, 다음에 다시 만나고 싶어지는가”를 개선해야 한다.

이 문서는 역할을 사용자로 전환한 전문가 평가다. 실제 일반 사용자 여러 명의 인터뷰나 통계적 사용성 테스트 결과는 아니다.

## 평가 방법과 한계

- 기존 localhost:8081 사용 기록과 분리한 localhost:8083 데모에서 신규 사용자 ‘지우’를 생성했다.
- 393 × 852 모바일 크기에서 온보딩, 홈, 위로 전화 선택, 목소리 미리 듣기, 캐릭터 생성, 30초 예약, 대기, 수신, 대화, 종료, 한마디 저장, 기록, 기억 삭제 선택지, 재예약, 두 번째 통화, 프로필, 작성 도중 탭 이동을 직접 조작했다.
- ‘도윤’이라는 가상의 대학 친구를 만들고, 가상의 회사 발표 이야기를 입력했다. 실제 개인정보나 외부 유료 전화는 사용하지 않았다.
- Moonline는 직접 체험했다. 비교 앱들은 공개 공식 가이드와 사용자가 제공한 설명을 기준으로 비교했다. 각 앱의 로그인 후 전체 기능이나 유료 팬미팅을 직접 사용했다고 주장하지 않는다.
- 실제 전화망 발신, iPhone/Android 실기기, 잠금화면, 진동, 알림 도달, 음색과 음성 지연은 이번 평가에서 검증하지 않았다. 음성 미리 듣기 UI와 재생 상태는 확인했지만 음질을 실청 평가하지 않았다.
- 현재 대화는 규칙형 데모다. 아래 대화 사례는 현재 데모의 경험 문제이며, 미연결 상태인 OpenAI 실제 통화의 성능 평가가 아니다.

## 1. 첫 방문과 홈

### 문제

‘누구에게 전화받고 싶나요?’라는 질문 아래의 주인공은 사람보다 사진과 상황 카테고리다. 감성적인 사진은 좋은 첫인상을 주지만, 첫 번째 추천 카드의 유용한 정보와 행동까지 가려진다. 영문 장식 제목은 시각적으로 크지만 실제 예약 결정에는 도움이 적다.

온보딩은 서비스의 약속을 설명하지만 세 장을 읽은 뒤에도 구체적인 통화 장면을 경험하지 못한다. 데모라는 설명은 세 번째 페이지에서 분명해진다. 처음부터 ‘앱 안에서 30초 뒤 체험’이라는 가벼운 기대를 잡아주는 편이 낫다.

### 개선

- 첫 화면 안에 이름/관계/한 줄 첫 인사/즉시 체험 버튼이 함께 보이게 한다.
- ‘바로 추천받기’와 ‘직접 만들기’를 별도 입구로 둔다. 추천을 택한 사용자에게는 모든 설정을 요구하지 않는다.
- 예시: ‘도윤 · 말없이 들어주는 오랜 친구 / 오늘은 네 이야기부터 듣고 싶어서 / 30초 뒤 체험’.
- 사진의 높이를 줄이거나 카드와 통합한다. 사진을 눌러도 아무 일도 일어나지 않는 큰 영역을 핵심 행동보다 앞세우지 않는다.
- 빈 기록 화면에는 ‘첫 전화 받아보기’라는 실제 행동을 제공한다.

## 2. 캐릭터 만들기

### 문제

현재는 캐릭터를 상상하는 즐거움보다 설정표 작성에 가깝다. 성격 태그를 여러 개 눌러도 말투가 어떻게 달라질지 보이지 않는다. ‘다정한’과 ‘차분한’이 어느 정도 다르고, ‘무뚝뚝한’과 함께 골라도 되는지 판단하기 어렵다. 배경과 첫 인사는 빈칸에서 사용자가 직접 써야 한다.

Character.AI 가이드는 첫 인사를 인물의 말투, 관계, 첫 장면을 보여주는 요소로 설명한다. Moonline는 첫 인사 미리보기를 이미 갖췄지만, 현재 체험에서는 내가 적은 문장이 그대로 표시되는 수준이라 설정의 효과를 확인하기 어렵다.

### 개선

- 기본 흐름: 이름 → 나와의 관계 → 말투 한 가지 → 첫 인사 고르기 → 시간.
- ‘더 자세히 만들기’ 안에 배경, 성격 조합, 기념일, 금지/선호 주제 등을 둔다.
- 추천 인물은 기본값을 충분히 제공한다. 직접 생성하고 싶은 사용자만 세밀하게 편집한다.
- 같은 첫 인사를 말투에 따라 2~3개 예시로 보여준다. 예: 담백함 ‘오늘 무슨 일이 있었어?’ / 다정함 ‘오늘 표정이 조금 지쳐 보이는 것 같아서. 천천히 말해도 돼.’ 단, 실제로 관찰하지 않은 외모/상태를 아는 듯한 문장은 사용 맥락에 맞게 제한한다.
- 배경 입력은 ‘언제 만났나요?’, ‘함께 기억할 일은?’ 같은 선택적 질문과 예시를 제공한다.
- 이름/프로필/목소리/첫 인사가 한 사람의 카드로 묶여야 한다. 시나리오가 바뀌어도 누구와 통화하는지 일관되게 보여준다.
- 작성 중에는 자동 임시 저장을 지원하고, 재방문 시 ‘이어서 만들기’를 제공한다.

## 3. 목소리 선택

### 문제

Joon을 미리 들은 뒤 ‘이 목소리로 할게요’를 누르면 Noah가 유지되는 흐름을 직접 재현했다. 재생과 선택을 분리할 수는 있지만, 버튼 문구와 선택 피드백은 그 차이를 명확하게 알려줘야 한다. 카드 안에 또 선택 박스가 있어 어느 부분을 누르는지에 따라 의미가 달라진다.

### 개선

- 카드 안에서 재생/선택의 두 동작을 명확히 구분한다.
- 선택된 목소리에 체크와 ‘선택됨’을 함께 표시한다. 화면 하단에는 ‘Noah로 계속’처럼 실제 선택값을 표시한다.
- 모든 목소리를 같은 한 문장으로 비교하고, 짧은 재생 시간과 중지 상태를 보여준다.
- 캐릭터 이름과 목소리 이름을 구분한다: ‘도윤의 목소리 · Noah’.
- 데모 음성과 실제 통화 음색이 다르다는 안내는 재생 버튼 가까이에 둔다. 현재는 목록을 내려야 안내가 보인다.

## 4. 예약 확인

### 문제

사용자가 이름까지 만든 뒤 마지막 요약이 목소리명과 상황 중심으로 돌아간다. 날짜/시간/상대/수신 방식이 한 번에 읽히는 최종 확인이 약하다. 기념일과 날짜의 직접 문자열 입력은 웹 체험에서 입력 부담을 준다. 네이티브 날짜 선택기는 이번 실기기 평가 대상이 아니다.

### 개선

예약 직전 하나의 문장으로 확인한다: ‘오늘 9월 15일 밤 10시, 도윤에게 전화가 와요.’ 아래에 목소리, 관계, 첫 인사, 수신 방식을 펼쳐 볼 수 있게 한다.

- 추천 시간에는 날짜를 포함한다. 자정은 어느 날짜인지 특히 명확해야 한다.
- 수정은 시간만 빠르게 바꿀 수 있게 한다.
- 재예약은 캐릭터를 유지한 채 시간 선택으로 바로 이동한다.
- 향후 실제 전화에서는 번호 인증과 알림 준비 여부를 예약 전에 확인한다. 기능 실패를 마지막 예약 버튼을 누른 뒤 처음 알려서는 안 된다.

## 5. 기다림 — 가장 중요한 개선 영역

### 현재 평가

사진과 유리 효과는 분위기를 만든다. 하지만 긴 영문 제목과 사진에 비해 상대 이름은 작다. ‘무엇을 기다리는가’보다 ‘멋진 대기 화면을 보고 있다’는 감각이 앞선다. 30초 체험에서는 준비 버튼을 발견하려고 스크롤하는 동안 시간이 줄어든다.

‘소리 확인’은 재생 시도와 확인 완료가 구분되지 않고, ‘여기서 기다릴게요’는 라벨 변경 외에 무엇을 뜻하는지 알기 어렵다. 앱의 다른 탭에 있어도 수신되는 것은 직접 확인했지만, 사용자에게 그 규칙이 충분히 설명되지 않는다.

### hellolive에서 가져올 것

공개 hellolive 안내는 실제 영상통화 전 테스트와 대기, 차례가 오면 수신하는 구조를 설명한다. Moonline가 가져와야 할 것은 대기실 모양보다 ‘내가 준비됐고, 다음에 무슨 일이 생기는지 안다’는 확신이다.

실제 휴대폰 전화는 전화망으로 수신된다. 영상통화 대기실처럼 앱을 계속 보고 있어야 하는 조건을 복제하면 Moonline의 장점을 잃는다. 향후 영상통화에서는 카메라/마이크/장치 상태가 필요하지만 현재 전화 대기에는 필요 없는 권한을 끼워 넣지 않는다.

### 제안하는 세 구간

| 남은 시간 | 우선 보여줄 것 | 행동 |
|---|---|---|
| 5분 이상 | 도윤, 약속 날짜/시간, 수신 방식 | 앱을 나가도 되는지 명확히 안내, 시간 변경 |
| 5분 이내 | 도윤 + 큰 남은 시간 + 필요한 준비 | 소리 테스트 → ‘잘 들려요 / 안 들려요’, 필요한 경우 도움 |
| 1분 이내 | 도윤 + 짧은 첫 인사 + 남은 초 | 설정/홍보 요소 축소, 큰 수신 준비 영역 |

실제 연결 상태가 없다면 ‘도윤이 접속했어요’ 같은 존재 표시를 만들지 않는다. 예약이 정상적으로 저장됨, 소리 테스트 응답, 실제 연결 진행처럼 확인 가능한 상태만 보여준다.

## 6. 수신과 통화

### 현재 평가

수신 전환은 동작하고 인물 이름도 나온다. 다만 대기의 영화 같은 장면이 이니셜 원과 일반 버튼으로 갑자기 바뀐다. 캐릭터마다 구별되는 상징/아바타/색을 유지하면 같은 사람이 도착한 느낌이 강해진다.

데모에서 받기를 누른 후 텍스트를 입력해야 한다는 점은 명시돼 있다. 그래도 ‘전화’를 기대한 사용자가 체감하는 핵심은 아직 검증하기 어렵다. 실제 음성 대화의 속도, 말 끊기, 침묵, 잘못 알아들었을 때 복구는 외부 서비스 연결 뒤 반드시 별도로 평가해야 한다.

대화가 길어지면 상단의 인물/시간은 화면 밖으로 가고 통화 제어는 메시지와 같이 스크롤된다. 빠른 답장은 상황과 무관하게 두 개가 반복되며 일부는 한 음절만 다음 줄로 내려갔다.

### 개선

- 이름/통화 상태와 종료 버튼을 고정한다. 자막/텍스트 기록은 필요할 때 펼친다.
- 음성 모드에서는 듣는 중/말하는 중/연결 중/재연결 필요 상태를 구분한다.
- 텍스트 체험은 예약 전에 기대치를 알려준다. 실제 음성 기능이 붙기 전까지 복잡한 입력을 요구해 음성 품질을 약속하지 않는다.
- 빠른 답장은 현재 대화에 맞게 바꾸거나 ‘그냥 들어줘 / 다른 이야기 / 오늘은 여기까지’처럼 의도가 분명한 선택을 준다.
- 종료 요청은 항상 즉시 접근 가능하게 한다.

## 7. 대화의 배려와 기억

### 직접 확인한 대화

입력: ‘오늘 회사 발표를 잘 마쳤는데 아무도 수고했다고 하지 않아서 서운했어.’
응답: ‘그중에서 가장 마음에 남은 순간은 뭐였어?’

입력: ‘그 이야기는 그만하고 싶어. 다른 얘기 하자.’
응답: ‘그리고 꼭 해주고 싶은 말이 있어. 오늘은 충분히 잘했어.’

입력: ‘내가 오늘 무슨 일을 잘 마쳤다고 했지?’
응답: ‘오늘 많이 버거웠구나. 해결하려고 애쓰지 말고 지금은 그냥 이야기해줘.’

이는 데모 응답의 한계다. 그러나 사용자 관점에서는 ‘많이 설정했는데 정작 내 이야기는 이해하지 못한다’는 결과로 남는다. 특히 주제 중단 요청은 어떤 데모에서도 미리 설정한 문장보다 우선해야 한다.

### 더 나은 대응의 예

- 첫 응답: ‘발표를 잘 마쳤는데도 아무도 알아주지 않아서 서운했구나. 준비하느라 많이 애썼겠다.’
- 주제 변경: ‘알겠어. 그 이야기는 여기까지 하자. 가벼운 얘기를 할까?’
- 사실 확인: ‘회사 발표를 잘 마쳤다고 했어. 그런데 수고했다는 말을 못 들어서 서운했다고 했지.’

### 기억의 문제

기억은 저장된 문장을 다시 읽는 것만으로 충분하지 않다. 두 번째 통화에서 ‘지난번 이야기 기억하고 있어’ 뒤에 과거 발언과 주제 중단 문장까지 그대로 붙었다. 이어지는 관계보다 기록을 읽어주는 인상을 준다.

- 사실: 회사 발표를 마쳤음.
- 감정: 인정받지 못해 서운했음.
- 선호: 해결책보다 먼저 들어주길 원함.
- 이번 대화의 요청: 그 주제는 지금 중단하고 싶음.

이 네 가지는 다르게 다뤄야 한다. 다음 통화에서는 ‘그 이야기 다시 해도 괜찮아?’처럼 사용자가 방향을 정할 수 있게 해야 한다. ‘그만하자’가 곧 데이터 삭제 동의 철회라는 뜻은 아니지만, 이후 대화 사용 방식에는 반영돼야 한다.

## 8. 기록과 관계의 지속

한마디 저장 기능과 기록 접근은 실제로 동작한다. 다만 첫 통화에서는 마지막 일반 응답이, 두 번째 9초 통화에서는 길고 어색한 첫 인사 전체가 ‘오늘의 한마디’가 됐다. 무조건 한마디를 채우기보다 의미 있는 문장을 사용자가 고르게 해야 한다.

- 종료 화면 제목: ‘오늘도 도윤과 잠깐 가까워졌어요’ 같은 관계 중심 표현을 검토하되, 실제 대화 내용에 맞게 사용한다.
- ‘도윤이 남긴 말’ 후보에서 한 문장을 선택하거나 저장하지 않을 수 있게 한다.
- 대화가 거의 없었다면 통화 정보만 남긴다.
- 다음 행동은 ‘도윤에게 다시 전화받기 → 시간만 선택’으로 단순화한다.
- 통화 내용은 저장하되 기억 사용만 끄기, 기억 하나 수정/삭제, 한마디만 보관하기를 분리한다.
- 캐릭터별로 관계/배경/기억/지난 통화/다음 예약을 볼 수 있는 공간이 필요하다.

## 9. 시각 디자인과 글꼴

산세리프로 바꾼 뒤 글자 자체의 분위기는 유리 질감과 더 잘 맞는다. 손글씨 패키지와 명조체는 제거했다. 현재 남은 문제는 글꼴보다 정보의 크기와 순서다.

- 영문 장식 제목보다 상대 이름과 다음 행동을 더 크게 보여준다.
- 모든 요소가 비슷한 크림색 유리 카드이면 눌러야 할 것과 정보가 구분되기 어렵다. 입력창/정보 카드/주요 버튼의 대비와 모양을 구분한다.
- 유리 위에 또 유리 박스를 넣는 중첩은 줄인다. 사진 위 유리는 살리고 일반 폼은 단순하게 한다.
- 작은 회색 글자, 넓은 자간의 영문 안내는 보조 정보로 제한한다. 햇빛 아래 실기기와 큰 글자 설정에서 대비/줄바꿈을 추가 확인해야 한다. 이번에는 수치 기준의 대비 검사를 하지 않았다.
- ‘오늘 좀 힘들었어’처럼 한 음절이 다음 줄로 내려가는 버튼은 짧은 라벨 또는 충분한 폭을 사용한다.
- 상단 안내가 끝난 통화나 새 설정 화면까지 남아 있는 문제를 정리한다. 안내는 해당 상태에만 보여야 한다.
- 같은 사진을 모든 캐릭터에 반복하는 대신, 인물별로 색/상징/사진 테마를 적절히 구별한다. 사실적인 인물 사진이 꼭 필요한 것은 아니다.

## 11. 우선순위

P0는 사용자 약속/통제/입력 보존에 직접 영향을 주는 문제, P1은 첫 이용과 재방문을 크게 방해하는 문제, P2는 완성도 개선이다. 실제 일반 사용자 데이터로 산정한 점수는 아니다.

### P0 — 다음 사용자 테스트 전

1. 주제 중단/종료 요청을 미리 설정한 문장보다 우선한다.
2. 듣고 선택한 목소리에 대한 명확한 확신을 준다. 선택값을 버튼에 표시한다.
3. 작성 중 자동 저장과 복귀를 보장한다.
4. 데모의 체험 범위를 시작 전에 설명하고, 소리 재생 시도와 확인 완료를 구분한다.
5. 끝난 통화에서 ‘대화를 계속할 수 있다’는 안내가 남지 않게 한다.

### P1 — 핵심 경험 개편

1. 추천 전화는 최소 선택만으로 첫 통화에 도달하게 한다.
2. 마지막 1분의 대기 화면을 이름/시간/준비 중심으로 만든다.
3. 통화 제어를 고정하고, 인물의 시각적 정체성을 수신/통화/기록까지 유지한다.
4. 동일 캐릭터 재예약을 시간 선택으로 단축한다.
5. 기억의 항목별 수정/삭제/사용 여부를 제공하고, 자연스럽게 대화에 반영한다.

### P2 — 이후 개선

캐릭터별 테마, 의미 있는 한마디 선택, 기념일의 실제 사용 경험, 기록 검색/인물별 필터, 모션/효과음의 취향 설정, 접근성 실기기 검증.

영상통화·실제 아티스트 연동을 먼저 늘리기보다 위 기본 경험을 먼저 검증하는 편이 타당하다. 이번 리뷰에서는 새 기능을 구현하지 않았다.

## 12. 다음 사용성 테스트 제안

실제 신규 사용자 5명 정도로 다음 가설을 확인한다. 숫자는 향후 테스트 설계 제안이지 이번 결과가 아니다.

1. 설명 없이 추천 전화를 예약하게 하고, 첫 의미 있는 행동까지 걸린 시간을 측정한다.
2. 미리 듣기 후 ‘누구의 어떤 목소리를 골랐나요?’라고 확인한다.
3. 대기 화면에서 ‘앱을 닫아도 되나요? 어떻게 수신하나요? 소리는 확인됐나요?’를 물어본다.
4. 대화 중 주제를 바꾸고, 끊고, 다시 받는 행동을 수행하게 한다.
5. ‘이 대화는 남기고, 발표 이야기만 다음 통화에서 쓰지 않게 해보세요’라는 과제를 준다.
6. 같은 사람에게 다시 예약할 때 필요한 터치/입력/스크롤과 주저하는 지점을 관찰한다.

목표 가설: 추천 체험의 준비를 1분 안팎으로 줄이기, 동일 인물 재예약은 시간 선택 중심의 짧은 흐름으로 만들기, 대기 중 수신 방식에 관한 오해를 없애기. 실제 수치는 테스트 후 조정한다.
