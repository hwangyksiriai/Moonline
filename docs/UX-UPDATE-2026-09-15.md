# UX 개선 적용 · 2026-09-15

## 이번에 적용한 변화

- 홈 첫 화면에 전화 체험과 직접 만들기 진입을 배치하고, 장식용 포스터는 아래로 이동했다.
- 추천 전화는 기본 상대·목소리·첫 인사를 준비한 상태에서 시간 단계로 진입한다. 기존 상대 재예약과 예약 수정도 시간부터 확인한다.
- 직접 만들기는 이름·관계·성격·첫 인사 → 목소리 → 상황 → 시간 순서다. 함께한 이야기·호칭·기념일·꼭 듣고 싶은 말은 상세 설정에 접었다.
- 초안은 계정과 작성 맥락(추천 상황, 상대, 수정 예약)별로 기기에 자동 저장한다. 탭 이동과 재시작 뒤 같은 진입점을 열면 복원한다. 새로 쓰기와 예약 완료 시 해당 초안을 초기화한다. 클라우드 기기 간 동기화는 아니다.
- 목소리 미리 듣기는 해당 목소리 선택도 함께 수행한다. 계속 버튼·시간 요약에 선택한 이름을 표시한다.
- 작성 화면의 다음/예약 버튼을 하단에 고정했다. 예약 단계에서는 선택 시간과 상대도 함께 표시한다.
- 대기 화면은 상대·남은 시간·실제 예약 일시를 먼저 보여준다. 데모는 앱을 열어 둬야 하고, 실제 모드는 휴대폰에서 받는다는 차이를 설명한다.
- 소리 시험은 재생 요청만으로 성공 처리하지 않는다. 사용자가 잘 들림/안 들림을 선택하고, 안 들리면 복구 안내를 보여준다.
- 데모 통화의 이름·상태·입력·종료 조작은 고정하고 대화만 스크롤한다. 종료된 음성 재생에서 발생한 오류가 다른 화면까지 남지 않도록 재생 세대와 화면 상태를 구분했다.
- 데모 응답에서는 중단/주제 변경/종료 요청을 정해 둔 대사보다 우선한다. 명시적인 통화 종료 요청은 실제 종료 동작으로 이어진다.
- 질문·종료 요청을 지속 기억으로 저장하지 않는다. 규칙 기반 데모는 주제 중단 요청이 있으면 그 통화의 자동 기억 생성을 보수적으로 생략한다. 정교한 주제별 사실 추출을 지원하는 것은 아니다.
- 대화 없이 끊은 통화에서 시나리오를 기억으로 만들거나 첫 인사를 한마디로 저장하지 않는다.
- 기억 수정·한 줄 삭제·다음 통화 사용 여부를 대화 원문과 분리했다. 실제 모드용 소유자 검증 API와 처리 중 편집 충돌 방지도 추가했다.
- 한마디는 실제 대화 후보에서 다시 선택하거나 남기지 않을 수 있다. 기록에 상대별 필터를 추가했다.
- 기존 저장 기록을 소급해 덮어쓰지 않는다. 새 통화부터 개선된 생성 규칙을 적용한다.

## 검증

- 앱 TypeScript 검사 통과.
- 앱 단위/회귀 테스트 16개 통과: 종료·중단 우선순위, 빈 통화, 기억 제외, 실제 발화 기반 한마디, 이전 발화 확인 포함.
- 서버 TypeScript 검사 및 테스트 9개 통과: 소유자 분리, 기억 편집 후 원문 보존, 없는 발화 선택 거부 포함.
- localhost:8083의 별도 체험 데이터로 390×844 화면 검증: 초안 탭 이동/새로고침 복원, Joon 미리 듣기 선택 유지, 민서 예약, 30초 대기→수신→통화, 소리 실패 안내, 글로 종료 요청→종료 화면, 기억 수정 후 원문 유지, 동일 상대 재예약의 시간 단계 진입.
- 브라우저에서 실제 소리를 청취하거나 iPhone/Android 실기기의 키보드·블루투스·백그라운드 전화 수신을 검증한 것은 아니다.
- 외부 계정이 없으므로 실제 통신사 발신, 실시간 AI 통화 품질, 비용과 음성 복제는 아직 실서비스 검증 전이다.
