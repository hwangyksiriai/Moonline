# 체험 대화 수정 · 2026-09-16

## 원인

`mockReply`는 입력 의도와 무관하게 시나리오별 두 답변을 사용자 발화 횟수로 순환했다. 위로 시나리오에서 “고마워 → 다른 얘기 하자 → 아 보고싶어”를 보내면 감사와 그리움에 같은 답변이 나왔다. 두 번째 발화부터 필수 문구가 질문을 덮어쓰는 문제도 있었다.

## 변경

- 감사, 그리움, 캐릭터 정체, 감정, 조언/경청 요청, 음악/음식 등의 입력을 구분한다.
- 짧은 답변은 직전 질문에 연결한다. 명시적인 새 입력과 중단·종료 요청을 우선한다.
- 이미 보낸 후보 문장을 반복 순환하지 않는다. 답변 범위를 벗어난 질문에는 체험 한계를 설명한다.
- 필수 문구는 위로 응답에 한 번 덧붙이며 직접 질문을 대체하지 않는다.
- 주제 전환 이후 회상에서 이전 주제를 다시 꺼내지 않는다.
- “일” 한 글자를 업무로 인식하던 로직을 제거했다. “회사 가기 싫어”와 “이 얘기는 그만하자”를 구분한다.
- 직전 답변에 맞는 선택지를 표시하며 별도 주제 전환 버튼을 유지한다. 새 발화를 보내면 이전 읽기 음성을 멈춘다.
- 화면에 `체험 대화 · AI 미연결`과 자유 대화의 한계를 표시한다.

## 범위

이 변경은 계정 없이 실행되는 **규칙형 체험**의 오류 수정이다. 언어 모델에 연결한 자유 대화, 음성 인식, 실제 전화 연동을 구현하거나 검증한 것으로 간주하지 않는다. API 키나 개인 대화를 외부로 전송하지 않는다.

## 검증

- 앱 타입 검사 및 테스트 26개 통과. 신고된 입력 순서, 반복, 문구 우선순위, 짧은 답변, 감정 부정 표현, 회상 경계, 미지원 질문을 포함한다.
- 서버 타입 검사 및 테스트 12개 통과. 공유 주제 전환 판별 변경에 대한 기존 서버 회귀 검사도 수행했다.
- 별도 로컬 테스트 프로필에서 실제 브라우저 입력 `고마워 → 다른 얘기 하자 → 아 보고싶어 → 너`의 응답을 확인했다. `이제 통화 끊자`로 종료되며 저장 미동의 대화가 남지 않는 것도 확인했다.
- 390×844 모바일 크기에서 최신 답장, 대화 선택지, 입력창과 종료 버튼이 표시되는 것을 확인했다. 실기기 키보드/음성 출력 검증은 별도다.
