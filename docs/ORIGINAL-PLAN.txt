# 프로젝트명

**밤편지**

## 한 줄 정의

사용자가 원하는 목소리, 상황, 시간을 설정하면 **예약한 시간에 실제 휴대폰으로 전화가 걸려오고 AI와 실시간으로 대화할 수 있는 모바일 서비스**.

핵심은 AI 기능 자체가 아니라,

**“기다리던 시간에 정말 전화가 울리는 경험”**

이다.

---

# 1. 이번 개발 목표

처음부터 모든 기능을 만들지 않는다.

이번 MVP에서는 아래 경험이 실제로 동작하도록 구현한다.

### 핵심 Flow

사용자 가입

→ 전화 시나리오 선택

→ 목소리 선택

→ 원하는 상황 입력

→ 전화 받을 시간 선택

→ 전화 예약

→ 예약 시간까지 기다림

→ 실제 휴대폰으로 전화 수신

→ AI와 실시간 음성 대화

→ 전화 종료

→ 통화 기록 확인

이 Flow가 처음부터 끝까지 실제로 동작하는 것이 MVP의 목표다.

---

# 2. 제품 컨셉

일반적인 AI 챗봇처럼 보이면 안 된다.

ChatGPT처럼 대화를 입력하는 서비스가 아니라

**“누군가 나에게 전화한다”**

는 경험에 집중한다.

UI에서 다음과 같은 기술적인 단어는 최대한 노출하지 않는다.

* AI
* Prompt
* TTS
* Voice Model
* LLM
* Voice Clone

대신 사용자에게 보여주는 요소는 다음 네 가지다.

**사람**

**상황**

**감정**

**시간**

# 12. 기본 AI System Prompt

다음과 같은 구조를 사용한다.

당신은 실제 전화 통화 속 인물이다.

사용자는 당신이 AI라는 느낌을 받아서는 안 된다.

현재 관계:
{{relationship}}

캐릭터 성격:
{{personality}}

현재 상황:
{{scenario}}

이번 전화의 목적:
{{goal}}

사용자 이름:
{{userName}}

반드시 자연스럽게 포함해야 하는 말:
{{mustSayPhrase}}

대화 원칙:

1. 전화 통화처럼 짧고 자연스럽게 말한다.

2. 한 번에 긴 문장을 말하지 않는다.

3. 사용자의 말을 듣고 상황에 맞게 답한다.

4. 같은 질문을 반복하지 않는다.

5. 사용자의 말을 그대로 반복하지 않는다.

6. 지나치게 상담사처럼 말하지 않는다.

7. 실제 사람처럼 웃음, 머뭇거림, 짧은 침묵을 활용한다.

8. 자연스럽게 먼저 새로운 화제를 꺼낼 수 있다.

9. 현재 설정된 캐릭터의 성격을 유지한다.

10. 상황을 벗어나지 않는다.

첫 문장은 너무 길지 않게 한다.

예:

“여보세요?”

사용자가 반응하면 그때부터 자연스럽게 상황을 시작한다.

# 16. 통화 기억

DB에 전체 통화 Transcript를 저장한다.

통화 종료 후 AI가 Summary를 생성한다.

예:

사용자는 오늘 직장에서 상사에게 혼났고 많이 지쳐 있었다.

내일 오전 10시에 중요한 발표가 있다.

최근 잠을 제대로 자지 못하고 있다.

다음 전화에서 AI가 이 Summary를 활용할 수 있게 한다.

예:

다음 통화:

“오늘 발표 있다고 했잖아. 잘 끝났어?”

이 기능은 MVP에서도 기본적인 형태로 구현한다.

# 22. API Key가 없어도 실행 가능하도록 만들기

중요.

**DEMO MODE**

를 구현한다.

.env:

DEMO_MODE=true

Demo Mode에서는 실제 전화 대신

예약 시간에 Push Notification을 보내고

앱 내부 Fake Incoming Call 화면을 띄운다.

사용자가 전화를 받으면 Mock AI Conversation 화면으로 진입한다.

나중에 실제 API Key를 넣으면

Demo Mode → Real Call Mode

로 전환될 수 있게 설계한다.

# 33. 구현 시 중요한 조건

모든 화면은 실제 모바일 크기를 기준으로 구현한다.

iPhone 15 Pro 정도를 기준으로 디자인한다.

Android에서도 레이아웃이 깨지면 안 된다.

Loading / Empty / Error State를 반드시 만든다.

API가 실패해도 앱이 강제 종료되지 않도록 한다.

시간대는 사용자 timezone 기준으로 처리한다.

예약 전화가 중복 실행되지 않게 한다.

전화 발신 Webhook은 중복 호출에 대응할 수 있도록 idempotent하게 작성한다.

API Key와 개인정보는 Client에 노출하지 않는다.

전화번호는 Backend에서 관리한다.

# 34. 개인정보 및 음성 관련

통화 녹음 및 Transcript 저장은 사용자가 동의한 경우에만 진행하도록 구조를 만든다.

향후 Custom Voice 기능을 만들 경우

본인 또는 사용 권한이 있는 음성만 등록할 수 있도록 동의 절차가 필요하다.

유명인이나 제3자의 음성을 무단으로 복제하는 기능은 구현하지 않는다.
